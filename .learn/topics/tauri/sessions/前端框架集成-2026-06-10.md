## Positioning

**前端框架集成** 是「项目结构与开发环境」分支的最后一个概念。你已经学会了创建项目、理解目录结构、配置 tauri.conf.json，现在要掌握：**Tauri 如何与 React/Vue/Svelte 等前端框架配合工作？有什么需要注意的特殊事项？**

Tauri 的设计理念是"前端框架无关"，但不同框架在集成时有一些细节差异。

## Analogy

把 Tauri 与前端框架的集成想象成**汽车与导航系统的关系**。

Tauri 是汽车（提供动力、底盘、安全系统），前端框架是导航系统（React、Vue、Svelte 等）。

- 汽车不关心你用什么导航（框架无关）
- 导航系统需要适配汽车的接口（Tauri API）
- 安装导航需要遵循汽车的规范（构建配置）
- 导航坏了可以换一个，汽车照样能开（框架可替换）

关键：**接口标准化**。只要前端框架能输出 HTML/CSS/JS，就能和 Tauri 配合。

## Core Mechanism

### 一、Tauri 对前端框架的要求

Tauri 对前端框架只有一个核心要求：

**能构建出静态 HTML/CSS/JS 文件。**

```
前端框架源码 → 构建工具（Vite/Webpack）→ 静态文件（dist/）→ Tauri 加载
```

这意味着：
- ✅ React（Vite/Webpack 构建）
- ✅ Vue（Vite/Webpack 构建）
- ✅ Svelte/SvelteKit
- ✅ Solid
- ✅ Preact
- ✅ Angular
- ✅ Astro
- ✅ Next.js（静态导出模式）
- ✅ Nuxt（静态生成模式）
- ❌ Next.js（SSR 模式，需要 Node.js 服务器）
- ❌ 纯 SPA 但没有构建步骤（可以用 Vanilla 模板）

### 二、集成方式

#### 方式 1：使用 create-tauri-app（推荐）

```bash
npm create tauri-app
# 选择框架：React / Vue / Svelte / Solid / Preact / Vanilla
```

脚手架会自动配置好：
- 前端框架依赖
- Vite 配置
- Tauri 配置
- 基础代码模板

#### 方式 2：已有项目添加 Tauri

```bash
# 1. 安装 Tauri CLI 和 API
npm install -D @tauri-apps/cli
npm install @tauri-apps/api

# 2. 初始化 Tauri 项目
npx tauri init
```

按提示配置：
- 应用名称
- 窗口标题
- 前端资源目录（如 `../dist`）
- 开发服务器 URL（如 `http://localhost:5173`）
- 开发命令（如 `npm run dev`）
- 构建命令（如 `npm run build`）

### 三、各框架集成要点

#### React

**项目结构：**
```
src/
├── main.tsx          # 入口
├── App.tsx           # 主组件
└── components/       # 组件目录
```

**关键配置（vite.config.ts）：**
```typescript
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  // 防止 Vite 遮蔽 Tauri 的 API
  clearScreen: false,
  server: {
    port: 1420,  // 确保端口与 tauri.conf.json 的 devUrl 匹配
    strictPort: true,
  },
});
```

**Tauri API 使用：**
```tsx
import { invoke } from "@tauri-apps/api/core";
import { useState } from "react";

function App() {
  const [result, setResult] = useState("");

  async function handleClick() {
    const res = await invoke<string>("greet", { name: "React" });
    setResult(res);
  }

  return (
    <div>
      <button onClick={handleClick}>Greet</button>
      <p>{result}</p>
    </div>
  );
}
```

#### Vue

**项目结构：**
```
src/
├── main.ts           # 入口
├── App.vue           # 主组件
└── components/       # 组件目录
```

**关键配置（vite.config.ts）：**
```typescript
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [vue()],
  clearScreen: false,
  server: {
    port: 1420,
    strictPort: true,
  },
});
```

**Tauri API 使用：**
```vue
<script setup lang="ts">
import { invoke } from "@tauri-apps/api/core";
import { ref } from "vue";

const result = ref("");

async function greet() {
  result.value = await invoke<string>("greet", { name: "Vue" });
}
</script>

<template>
  <div>
    <button @click="greet">Greet</button>
    <p>{{ result }}</p>
  </div>
</template>
```

**项目结构：**

```
src/

```

**Tauri API 使用：**

### 四、通用配置要点

#### 1. Vite 配置（所有框架通用）

```typescript
// vite.config.ts
import { defineConfig } from "vite";

export default defineConfig({
  // 防止 Vite 清除屏幕，保留 Tauri 日志
  clearScreen: false,
  
  // 开发服务器配置
  server: {
    port: 1420,      // 固定端口
    strictPort: true, // 端口被占用时报错，而不是自动换端口
  },
  
  // 生产构建配置
  build: {
    // 目标浏览器支持（Tauri 使用系统 WebView）
    target: ["es2021", "chrome100", "safari13"],
    // 不在生产环境生成 sourcemap
    sourcemap: false,
    // 压缩选项
    minify: "esbuild",
  },
  
  // 环境变量前缀（Tauri 推荐用 VITE_ 前缀）
  envPrefix: ["VITE_", "TAURI_"],
});
```

#### 2. tauri.conf.json 配置

```json
{
  "build": {
    "frontendDist": "../dist",
    "devUrl": "http://localhost:1420",
    "beforeDevCommand": "npm run dev",
    "beforeBuildCommand": "npm run build"
  }
}
```

**关键：**
- `devUrl` 的端口必须与 Vite 配置的 `server.port` 一致
- `frontendDist` 必须与 Vite 的 `build.outDir` 一致（默认 `dist`）

#### 3. TypeScript 配置

```json
// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2021",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "jsx": "react-jsx",  // 或 "preserve" 对于 Vue
    "types": ["@tauri-apps/api"]
  },
  "include": ["src"]
}
```

### 五、Tauri API 与框架的集成模式

#### 模式 1：直接调用（简单场景）

```typescript
import { invoke } from "@tauri-apps/api/core";

async function fetchData() {
  return await invoke<string>("get_data");
}
```

#### 模式 2：封装为 Hook/Composable（推荐）

**React Hook：**
```typescript
// hooks/useTauri.ts
import { invoke } from "@tauri-apps/api/core";
import { useState, useCallback } from "react";

export function useTauriCommand<T>(command: string) {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const execute = useCallback(async (args?: Record<string, unknown>) => {
    setLoading(true);
    setError(null);
    try {
      const result = await invoke<T>(command, args);
      setData(result);
      return result;
    } catch (e) {
      setError(String(e));
      throw e;
    } finally {
      setLoading(false);
    }
  }, [command]);

  return { data, loading, error, execute };
}

// 使用
function MyComponent() {
  const { data, loading, execute } = useTauriCommand<string>("greet");
  
  return (
    <button onClick={() => execute({ name: "React" })} disabled={loading}>
      {loading ? "Loading..." : data || "Greet"}
    </button>
  );
}
```

**Vue Composable：**
```typescript
// composables/useTauri.ts
import { invoke } from "@tauri-apps/api/core";
import { ref } from "vue";

export function useTauriCommand<T>(command: string) {
  const data = ref<T | null>(null) as Ref<T | null>;
  const loading = ref(false);
  const error = ref<string | null>(null);

  async function execute(args?: Record<string, unknown>) {
    loading.value = true;
    error.value = null;
    try {
      const result = await invoke<T>(command, args);
      data.value = result;
      return result;
    } catch (e) {
      error.value = String(e);
      throw e;
    } finally {
      loading.value = false;
    }
  }

  return { data, loading, error, execute };
}
```

#### 模式 3：事件监听集成

```typescript
// hooks/useTauriEvent.ts
import { listen, type UnlistenFn } from "@tauri-apps/api/event";
import { useEffect, useState } from "react";

export function useTauriEvent<T>(eventName: string) {
  const [payload, setPayload] = useState<T | null>(null);

  useEffect(() => {
    let unlisten: UnlistenFn | undefined;

    async function setup() {
      unlisten = await listen<T>(eventName, (event) => {
        setPayload(event.payload);
      });
    }

    setup();

    return () => {
      unlisten?.();
    };
  }, [eventName]);

  return payload;
}
```

### 六、框架特定的注意事项

#### React

- **Strict Mode**：开发模式下组件会渲染两次，Tauri invoke 也会调用两次。生产不受影响。
- **状态管理**：Tauri 事件更新状态时，注意使用函数式更新避免闭包陷阱。

#### Vue

- **响应式**：Tauri 返回的数据是普通对象，需要用 `ref` 或 `reactive` 包装才能响应式。
- **Composition API**：推荐用 Composition API 封装 Tauri API。

#### Svelte

- **响应式**：Svelte 的响应式基于赋值，Tauri 返回的数据直接赋值即可触发更新。
- **Stores**：可以用 Svelte stores 管理 Tauri 状态。

#### Solid

- **信号**：用 `createSignal` 包装 Tauri 返回的数据。
- **资源**：可以用 `createResource` 处理异步 Tauri 命令。

### 七、热更新（HMR）注意事项

**开发模式下：**
- 前端代码修改 → Vite HMR → WebView 热更新（不重启应用）
- Rust 代码修改 → 重新编译 → 重启应用窗口
- tauri.conf.json 修改 → 重启应用

**HMR 失效的常见原因：**
1. 端口冲突：Vite 自动切换了端口，但 tauri.conf.json 的 devUrl 没更新
2. 文件监听问题：某些系统文件监听可能失效，需要手动重启
3. Rust 编译错误：Rust 编译失败会导致应用无法启动

### 八、生产构建流程

```
npm run tauri build
    ↓
1. 执行 beforeBuildCommand（如 npm run build）
    ↓
2. 前端构建输出到 frontendDist（如 dist/）
    ↓
3. Tauri 编译 Rust 代码
    ↓
4. 前端资源嵌入 Rust 二进制
    ↓
5. 生成平台安装包（msi/dmg/deb 等）
```

**构建产物位置：**
```
src-tauri/
└── target/
    └── release/
        ├── bundle/
        │   ├── msi/           # Windows MSI 安装包
        │   ├── nsis/          # Windows NSIS 安装包
        │   ├── app/           # macOS 应用包
        │   ├── dmg/           # macOS DMG
        │   ├── deb/           # Linux DEB
        │   └── appimage/      # Linux AppImage
        └── my-app             # 可执行文件（未打包）
```

## Code Example

**完整的 React + Tauri 集成示例：**

```typescript
// src/hooks/useTauri.ts
import { invoke } from "@tauri-apps/api/core";
import { listen, type UnlistenFn } from "@tauri-apps/api/event";
import { useState, useEffect, useCallback } from "react";

// 通用命令 Hook
export function useCommand<T>(command: string) {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const execute = useCallback(async (args?: Record<string, unknown>) => {
    setLoading(true);
    setError(null);
    try {
      const result = await invoke<T>(command, args);
      setData(result);
      return result;
    } catch (e) {
      const errMsg = String(e);
      setError(errMsg);
      throw e;
    } finally {
      setLoading(false);
    }
  }, [command]);

  return { data, loading, error, execute };
}

// 事件监听 Hook
export function useEvent<T>(eventName: string) {
  const [payload, setPayload] = useState<T | null>(null);

  useEffect(() => {
    let unlisten: UnlistenFn | undefined;

    async function setup() {
      unlisten = await listen<T>(eventName, (event) => {
        setPayload(event.payload);
      });
    }

    setup();

    return () => {
      unlisten?.();
    };
  }, [eventName]);

  return payload;
}
```

```tsx
// src/App.tsx
import { useCommand, useEvent } from "./hooks/useTauri";

interface Task {
  id: number;
  title: string;
  completed: boolean;
}

function App() {
  // 使用命令 Hook
  const { data: tasks, loading, execute: loadTasks } = useCommand<Task[]>("get_tasks");
  const { execute: addTask } = useCommand<Task>("add_task");
  
  // 监听事件
  const newTask = useEvent<Task>("task-created");

  useEffect(() => {
    loadTasks();
  }, []);

  useEffect(() => {
    if (newTask) {
      // 新任务创建时刷新列表
      loadTasks();
    }
  }, [newTask]);

  async function handleAdd() {
    const title = prompt("Task title:");
    if (title) {
      await addTask({ title });
    }
  }

  if (loading) return <div>Loading...</div>;

  return (
    <div>
      <h1>Tasks</h1>
      <button onClick={handleAdd}>Add Task</button>
      <ul>
        {tasks?.map((task) => (
          <li key={task.id}>
            {task.title} {task.completed && "✓"}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default App;
```

## Common Misconceptions

**误解 1：Tauri 只能和 React 配合。**
纠正：Tauri 支持任何能输出 HTML/CSS/JS 的前端框架。官方脚手架提供 React、Vue、Svelte、Solid、Preact、Vanilla 模板。

**误解 2：前端框架的代码需要特殊修改才能在 Tauri 中运行。**
纠正：普通的前端代码不需要修改。只有需要调用 Tauri API（invoke、listen 等）的地方需要导入 `@tauri-apps/api`。

**误解 3：开发模式下前端热更新和 Tauri 热更新是一回事。**
纠正：前端热更新是 Vite 的 HMR（不刷新页面），Tauri 的 Rust 代码修改需要重新编译和重启应用窗口。两者是独立的。

**误解 4：生产构建时前端代码和 Tauri 代码是分开打包的。**
纠正：生产构建时，前端构建产物（HTML/CSS/JS）会被嵌入到 Rust 二进制文件中。最终用户拿到的是一个单独的可执行文件（或安装包），不需要额外部署前端。

**误解 5：可以用 Next.js 的 SSR 模式配合 Tauri。**
纠正：Tauri 是桌面应用，没有 Node.js 服务器运行环境。Next.js 必须用静态导出模式（`next export`），或者用 SSG/SPA 模式。Nuxt 同理，需要用静态生成。

## Socratic Check

**检验问题 1：**
如果你有一个现有的 Vue 项目，想添加 Tauri 支持，需要修改哪些地方？

答案：主要步骤：(1) 安装 `@tauri-apps/cli` 和 `@tauri-apps/api`；(2) 运行 `npx tauri init` 生成 src-tauri 目录；(3) 确保 `tauri.conf.json` 的 `devUrl` 和 `frontendDist` 与 Vue 项目配置匹配；(4) 在需要调用 Tauri API 的地方导入 `@tauri-apps/api`。Vue 代码本身不需要修改。

**检验问题 2：**
为什么 Vite 配置中要设置 `strictPort: true`？

答案：如果端口被占用，Vite 默认会自动尝试下一个端口（如 1420 → 1421）。但 tauri.conf.json 的 `devUrl` 写死了 `http://localhost:1420`。如果 Vite 实际运行在 1421，Tauri 会加载错误的地址，导致白屏。`strictPort: true` 让 Vite 在端口被占用时报错，而不是静默切换。

## Quick Summary

- Tauri 支持任何能输出 HTML/CSS/JS 的前端框架
- 集成方式：create-tauri-app 创建新项目，或 npx tauri init 添加已有项目
- 关键配置：Vite 端口与 tauri.conf.json 的 devUrl 匹配
- 推荐使用 Hook/Composable 封装 Tauri API，提高代码复用性
- 开发模式：前端 HMR + Rust 重编译重启
- 生产构建：前端资源嵌入 Rust 二进制，生成单独安装包
