## Positioning

**src-tauri 目录结构** 位于 Tauri 知识树的 **项目结构与开发环境** 分支，紧接在「create-tauri-app 脚手架」之后。脚手架帮你生成了项目，现在要深入理解：**src-tauri 目录里每个文件是干什么的？为什么要这样组织？**

src-tauri 是 Tauri 应用的"心脏"——所有 Rust 代码、配置、图标、权限都在这里。

## Analogy

把 src-tauri 想象成**餐厅的后厨**。

前端的 `src/` 是营业大厅（顾客看到的地方），src-tauri 是后厨（顾客看不到，但所有核心操作都在这里）。

后厨里有：
- **菜谱和操作手册**（main.rs、lib.rs）—— 告诉厨师怎么做菜
- **厨房设备清单**（Cargo.toml）—— 列出需要什么工具
- **餐厅营业执照**（tauri.conf.json）—— 餐厅的基本信息和规则
- **厨房安全规范**（capabilities/）—— 哪些操作允许，哪些禁止
- **食材仓库**（icons/）—— 餐厅的标识和装饰
- **厨房装修施工队**（build.rs）—— 开业前的准备工作

## Core Mechanism

### 一、完整目录结构

```
src-tauri/
├── src/
│   ├── main.rs              # 应用入口（二进制入口）
│   └── lib.rs               # Tauri 应用核心逻辑（命令注册）
├── icons/
│   ├── 32x32.png            # 应用图标（多种尺寸）
│   ├── 128x128.png
│   ├── 128x128@2x.png
│   ├── icon.icns            # macOS 图标
│   ├── icon.ico             # Windows 图标
│   └── Square*              # Windows Store 图标
├── capabilities/
│   └── default.json         # 权限配置（Tauri v2）
├── Cargo.toml               # Rust 依赖配置
├── tauri.conf.json          # Tauri 应用配置
├── build.rs                 # 构建脚本
└── target/                  # 编译输出（gitignore）
```

### 二、核心文件详解

#### 1. main.rs — 应用入口

```rust
// src-tauri/src/main.rs

// 防止 Windows 上打开多个控制台窗口
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

fn main() {
    // 调用 lib.rs 中的 run 函数启动应用
    my_tauri_app_lib::run()
}
```

**作用：**
- 二进制程序的入口点（`cargo build` 生成可执行文件时的起点）
- `windows_subsystem = "windows"` 防止 Windows 上弹出控制台窗口
- 实际逻辑在 `lib.rs` 中，这里只是调用

**为什么分 main.rs 和 lib.rs？**
- `main.rs` 生成二进制可执行文件
- `lib.rs` 生成库（可以被测试、被其他代码引用）
- 移动端（Android/iOS）需要库形式，所以 Tauri 要求分离

#### 2. lib.rs — 应用核心逻辑

```rust
// src-tauri/src/lib.rs

use tauri::Manager;

// 命令定义
#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}

#[tauri::command]
async fn fetch_data(url: String) -> Result<String, String> {
    // 异步命令示例
    Ok(format!("Fetched from {}", url))
}

// 应用构建和启动
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        // 注册插件
        .plugin(tauri_plugin_http::init())
        .plugin(tauri_plugin_fs::init())
        // 注册命令
        .invoke_handler(tauri::generate_handler![
            greet,
            fetch_data,
        ])
        // 应用启动前的设置
        .setup(|app| {
            // 可以在这里获取窗口、设置初始状态等
            let main_window = app.get_webview_window("main").unwrap();
            println!("Main window: {:?}", main_window.title());
            Ok(())
        })
        // 启动应用
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

**作用：**
- 定义 Tauri 命令（`#[tauri::command]`）
- 注册插件（`.plugin()`）
- 配置应用构建器（`tauri::Builder`）
- 设置应用生命周期钩子（`.setup()`）

**这是你写 Rust 代码的主要地方。**

#### 3. Cargo.toml — Rust 依赖配置

```toml
[package]
name = "my-tauri-app"
version = "0.1.0"
description = "A Tauri App"
authors = ["Your Name"]
repository = ""
edition = "2021"
rust-version = "1.77.2"

[lib]
name = "my_tauri_app_lib"
crate-type = ["staticlib", "cdylib", "rlib"]

[build-dependencies]
tauri-build = { version = "2.0.0", features = [] }

[dependencies]
tauri = { version = "2.0.0", features = [] }
tauri-plugin-http = "2.0.0"
tauri-plugin-fs = "2.0.0"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
tokio = { version = "1", features = ["full"] }

[features]
default = ["custom-protocol"]
custom-protocol = ["tauri/custom-protocol"]
```

**关键配置说明：**

| 配置项 | 说明 |
|--------|------|
| `[package]` | 包的基本信息（名称、版本、作者） |
| `[lib]` | 库配置，`crate-type` 指定生成类型（移动端需要 cdylib） |
| `[build-dependencies]` | 构建时依赖（tauri-build 处理资源嵌入） |
| `[dependencies]` | 运行时依赖（tauri、插件、serde 等） |
| `[features]` | 功能开关（custom-protocol 用于生产模式加载本地文件） |

**这个文件很重要，下一个概念会详细讲解。**

#### 5. build.rs — 构建脚本

```rust
// src-tauri/build.rs

fn main() {
    // tauri-build 会：
    // 1. 处理 tauri.conf.json 配置
    // 2. 嵌入前端资源到二进制文件
    // 3. 生成必要的代码
    tauri_build::build()
}
```

**作用：**
- Cargo 构建脚本，在编译 Rust 代码之前运行
- `tauri_build::build()` 处理 Tauri 特有的构建任务
- 通常不需要修改，除非有特殊构建需求

#### 6. capabilities/default.json — 权限配置（Tauri v2）

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "http:default",
    {
      "identifier": "fs:default",
      "allow": [
        { "path": "$APPDATA/**" },
        { "path": "$DESKTOP/**" }
      ]
    },
    "dialog:default"
  ]
}
```

**作用：**
- Tauri v2 的安全模型核心
- 定义哪些窗口可以使用哪些 API
- 细粒度控制文件访问路径、Shell 命令等
- 下一个概念「安全模型」会详细讲解

### 三、文件依赖关系

```
main.rs
    ↓ 调用
lib.rs
    ↓ 使用
Cargo.toml (依赖)
    ↓ 配置
tauri.conf.json (应用配置)
    ↓ 引用
capabilities/ (权限)
    ↓ 引用
icons/ (图标)
    ↓ 构建时处理
build.rs
```

### 四、添加新功能的典型流程

**添加新命令：**
1. 在 `lib.rs` 中定义 `#[tauri::command]` 函数
2. 在 `invoke_handler` 中注册命令
3. 前端通过 `invoke()` 调用

**添加新插件：**
1. 在 `Cargo.toml` 中添加插件依赖
2. 在 `lib.rs` 的 `Builder` 中 `.plugin()` 注册
3. 在 `capabilities/default.json` 中添加权限
4. 前端安装对应的 npm 包并使用

**添加新窗口：**
1. 在 `tauri.conf.json` 的 `app.windows` 中添加窗口配置
2. 或在 `lib.rs` 中用 `WindowBuilder` 动态创建

## Code Example

**完整的项目结构示例（带自定义命令和插件）：**

```
my-app/
├── src/                         # 前端
│   ├── main.tsx
│   ├── App.tsx
│   └── components/
│       ├── Header.tsx
│       └── Sidebar.tsx
├── src-tauri/                   # Rust 后端
│   ├── src/
│   │   ├── main.rs              # 入口
│   │   ├── lib.rs               # 核心逻辑
│   │   ├── commands/            # 命令模块（自定义添加）
│   │   │   ├── mod.rs
│   │   │   ├── file_ops.rs      # 文件操作命令
│   │   │   └── network.rs       # 网络请求命令
│   │   └── state.rs             # 共享状态（自定义添加）
│   ├── capabilities/
│   │   └── default.json
│   ├── icons/
│   ├── Cargo.toml
│   ├── tauri.conf.json
│   └── build.rs
├── package.json
└── vite.config.ts
```

**自定义的 lib.rs（模块化组织）：**

```rust
// src-tauri/src/lib.rs

mod commands;
mod state;

use tauri::Manager;

pub fn run() {
    tauri::Builder::default()
        // 注册共享状态
        .manage(state::AppState::new())
        // 注册插件
        .plugin(tauri_plugin_http::init())
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_dialog::init())
        // 注册命令（从 commands 模块导入）
        .invoke_handler(tauri::generate_handler![
            commands::file_ops::read_file,
            commands::file_ops::write_file,
            commands::network::fetch_url,
        ])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

## Common Misconceptions

**误解 1：main.rs 是写业务逻辑的地方。**
纠正：main.rs 只是入口，实际逻辑在 lib.rs。这样分离是为了支持移动端（需要库形式）。

**误解 2：src-tauri 目录名不能改。**
纠正：可以改，但需要同步修改 tauri.conf.json 和相关配置。脚手架生成的 `src-tauri` 是约定俗成的名字。

**误解 3：所有 Rust 代码都必须放在 src/ 下。**
纠正：可以创建子目录（如 `commands/`、`models/`、`utils/`）来组织代码。Rust 的模块系统支持任意目录结构。

**误解 4：Cargo.toml 中的依赖版本必须和脚手架生成的一样。**
纠正：可以升级或降级依赖版本，但要注意兼容性。Tauri 2.x 的插件需要匹配 Tauri 2.x 核心。

**误解 5：build.rs 必须保留，不能删除。**
纠正：build.rs 是 Cargo 构建脚本，`tauri_build::build()` 处理 Tauri 特有的构建任务（如资源嵌入）。删除会导致构建失败。

## Socratic Check

**检验问题 1：**
如果你想在项目中添加一个数据库操作模块，应该把代码放在哪里？

答案：建议在 `src-tauri/src/` 下创建 `db/` 或 `database/` 目录，放置数据库相关代码（如 `mod.rs`、`queries.rs`、`models.rs`）。然后在 `lib.rs` 中通过 `mod db;` 引入，并创建对应的命令（`#[tauri::command]`）暴露给前端。

**检验问题 2：**
`crate-type = ["staticlib", "cdylib", "rlib"]` 这三个类型分别是什么用途？

答案：`staticlib` 生成静态库（用于链接到可执行文件）；`cdylib` 生成动态库（C ABI，移动端需要）；`rlib` 生成 Rust 库（供其他 Rust 代码引用）。Tauri 需要这三种格式来支持桌面和移动端的构建。

## Quick Summary

- src-tauri 是 Tauri 应用的 Rust 后端目录
- main.rs 是入口，lib.rs 是核心逻辑（命令、插件、配置）
- Cargo.toml 管理 Rust 依赖，tauri.conf.json 管理应用配置
- capabilities/ 定义权限（Tauri v2 安全模型）
- icons/ 存放应用图标，build.rs 处理构建任务
- 可以创建子目录（commands/、models/ 等）组织代码
